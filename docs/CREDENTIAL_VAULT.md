# Website password vault (BUILT 2026-10-26, WIRED 2026-10-27; default OFF per tester)

Founder decision (2026-10-26): Friday may store a user's login for a website that needs a password, so the private browser can log in for them. This REVERSES the earlier rule "Friday never stores passwords" for website logins only. OTP, card numbers, UPI PIN and bank logins are still never stored.

## The flow
1. The browser flow needs a login and none is saved -> `CredentialService.request_link(user, site, hosts)` returns a one-time link `/connectors/credentials/<token>` (single use, 10 min, 5 tries, cross-site posts refused, `no-store`).
2. The user opens it on their phone and types username + password on that page and ticks the consent box. Never in WhatsApp chat, never through a tool argument, never to a model.
3. `CredentialVault.save` encrypts it (AES-GCM, field cipher, key from `FRIDAY_FIELD_KEY` / KMS) per (user, site); AAD binds it to that user and site; slot ids are blind indexes; a second encrypted "meta" blob lets the user see site names and a masked username (`ra***`), never the password.
4. In the browser worker `CredentialService.autofill(session, ...)` fills the site's own fields, only if the page host matches a host the login was saved for, only for the session's own user and site, only if switched on. The `Credential` object prints as `Credential(***)` and cannot be pickled. Audit records counts only.
5. "forget my logins" -> `CredentialService.forget(user[, site])` deletes slots and revokes open links. Entries also expire after 90 days.

## Refused always
Banks, UPI / payments, cards, government-ID sites (word list in `credentials.py::_BLOCKED_WORDS`, checked on the site key and every host). Edit the list with a test.

## Switches (`FRIDAY_BROWSER_*`, default off)
`CREDENTIALS_ENABLED=false`, `CREDENTIALS_ENABLED_USERS=` (ids or `*`; empty enables nobody; also needs `FRIDAY_BROWSER_ENABLED=true`), `CREDENTIALS_TTL_DAYS=90`, `CREDENTIALS_DIR=var/browser_credentials` (keep `var/` out of git), `CREDENTIALS_LINK_TTL_SECONDS=600`.
New: `LOGIN_OTP_IN_CHAT=false` and `LOGIN_OTP_CHAT_TTL_SECONDS=300` (a LOGIN code may be typed in the WhatsApp chat, see below). Per-site automation stays behind `FRIDAY_BROWSER_SITES_ENABLED` / `_LEGAL_CLEARED` / `_SUPERVISED` (docs/BROWSER_SITE_COVERAGE.md).

## Wiring (DONE 2026-10-27; everything behind the switches above)
- `friday serve` -> `InboundPipeline` builds `BrowserStack` (`friday/connectors/wiring.py`) only when `FRIDAY_BROWSER_ENABLED`; `create_app` calls `mount_browser` (`friday/api/browser_routes.py`): `/live/*` watch and takeover pages, `/connectors/otp/{token}`, `/connectors/credentials/{token}` (only when saved logins are on), `/connectors/qr/*`, `/ride/code/*`. `Runtime.start` calls `stack.start()` (registers `BrowserFlow` as the browser handler, starts `PauseWatcher`); `Runtime.stop` stops both and kills every session.
- The stack builds the `CredentialVault` from `FileVaultStore(credentials_dir)` + the live field cipher (`cipher_from_settings`: KMS key in production).
- "delete everything" (`InboundPipeline.delete_everything`) calls `BrowserStack.forget_user`: saved logins (also ones saved before the switch was turned off), saved browser sessions, open links, a pending login code, live sessions.
- Kill latch: `SessionManager.kill_all` latches until `revive()`; `PauseWatcher` lifts only its own latch.

## The secure page: what protects it
One-time token in the path (24 random bytes; unknown / expired / used all answer 404), bound to ONE user and ONE site, 10 minutes, 5 tries, single successful save. GET has no side effects. POST needs the per-link page token (CSRF field `t`, constant-time compare) and a same-site request (`Origin` and `Sec-Fetch-Site` checked). Per-client rate limit (`friday/api/page_security.py`: 40 requests / 10 min, 10 unknown-token requests / 10 min, then 429 with Retry-After); the client address is the last `X-Forwarded-For` entry only when the TCP peer is private/loopback (our proxy). Headers on every response: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, COOP/CORP same-origin, strict CSP (no scripts, no external loads, `form-action 'self'`). The body is capped (2 KB) and parsed by hand; nothing is echoed or logged. The form fits an iPad and a phone (viewport meta, inputs 20px so iOS does not zoom, no JavaScript, autocapitalize/autocorrect off). The same limiter guards the login-code page.

### Caddy route note (founder / installer)
`deploy/Caddyfile` proxies only listed paths; the secure pages are NOT reachable until you add them (they answer 404 while the browser switch is off). In the `@friday` matcher add:
`/connectors/credentials/* /connectors/otp/* /live/* /connectors/qr/* /ride/code/*` (the watch pages under `/connectors/watch/*` need the admin token and stay private). The link is `FRIDAY_PUBLIC_BASE_URL` + `/connectors/credentials/<token>`, so that URL MUST be `https://` (`friday doctor` fails otherwise). The token is in the URL path, so Caddy would write it to the access log: skip logging for these paths, e.g. `@secure path /connectors/credentials/* /connectors/otp/* /live/*` then `log_skip @secure` (before `handle`). Do not share the access log. Untested against a real Caddy / iPad (fakes and the test client only): open the link once on the founder's iPad before any tester uses it.

## WhatsApp commands (wording PENDING approval: `friday/connectors/login_copy.py`)
- "my logins" / "saved logins" / "mere logins": lists site names and a masked username (`ra***`), never a password.
- "save <site> login": sends the one-time secure page link (never asks in chat).
- "forget my logins": asks "delete all N?" with Yes / No buttons (or typed yes / haan / no / nahi, 2 minutes, anything else drops the question); on yes deletes all logins AND saved browser sessions. "forget <site>" (also "forget my zomato login", "zomato login bhool jao") does the same for one site. A word that is not a site ("forget it") is left to the normal chat. "my logins" / "forget" still work after the switch is turned off if something was saved before.

## Login code typed in the chat (founder decision 2026-10-27; `FRIDAY_BROWSER_LOGIN_OTP_IN_CHAT`, default OFF)
Passwords go ONLY to the secure page. A one-time LOGIN code for a site the user asked Friday to use may be typed in the chat, under these code-enforced guards (`friday/connectors/otp.py`, `BrowserStack.intercept_chat_secret`, hooks in `friday/api/inbound.py` and `friday/api/runtime.py`; tests `tests/api/test_login_otp_chat.py`):
1. Accepted only while a pending-login exists for THAT user (`PendingLoginRegistry`, set by `BrowserFlow` when it starts a login and asks for the code; ~5 min; cleared when the task ends or the user is forgotten). A 4-8 digit number with nothing pending is an ordinary message.
2. Single use: consumed on the first accepted code, placed straight into `OneTimeOtpChannel` for the browser worker. Never the LLM, never a handler after it, not logged (the audit line carries user id and site only).
3. The message is recognised in the webhook BEFORE it is queued (the job queue would otherwise store the raw text) and again in the pipeline; the stored chat row says `[redacted]`. The copy inside WhatsApp / Meta cannot be deleted by us: the acknowledgement says so (consent wording pending; legal read still needed: DPDP and WhatsApp retention).
4. Accepted shapes: `4821`, `otp hai 4821`, `mera otp 4821 hai`, Devanagari / Arabic-Indic / full-width digits, digits split by spaces, dashes or dots, zero-width characters, digit words ("four eight two one", "ek do teen char"). Anything else in the message (a sentence, a second number, over 80 characters) means it is not a code.
5. Never accepted, with or without a pending login, answered with a pointer to the secure page or the user's own app and stored redacted: bank / payment / transaction codes, UPI PIN / M-PIN / ATM PIN, card numbers (13-19 digits passing the Luhn check, or after "card number"), CVV / CVC, Aadhaar numbers and Aadhaar codes, passwords (a password word followed by a value, in English, Hinglish or Devanagari).
6. A PIN prompt of Friday's own (delete everything) wins: while one is open the digits are not given to the browser.
7. For the separate guardrails module: `friday.connectors.otp.classify_chat_secret(text, login_site=None)` returns a verdict (kind only, the code never prints or pickles) and `chat_secret_kind(text, login_pending=False)` returns just the kind (`login_otp`, `refuse_payment_otp`, `refuse_upi_pin`, `refuse_card`, `refuse_aadhaar`, `refuse_password`, `none`). Pure functions, no state, no I/O. The existing one-time code page stays as the alternative; the login message gets one extra line only when the switch is on.
Known limits: the heuristics are word lists (a bank code written with no bank, code or pin word and a pending login is taken as a login code: it is sent to the site the user is logging into, nowhere else); voice notes are transcribed first, so a spoken code works the same way (the audio stays in WhatsApp); a restart forgets the pending login (the user asks again).
