Founder ask: "make this bot PROACTIVE: what to keep in memory, how to use it to nudge, and all."
Builds on (not repeated): `friday/proactive/` (engine, triggers, guardrails, retention, vendor_triggers), `docs/PROACTIVE_AND_INBOUND_DESIGN.md`, `docs/LIFE_STATE.md`, `docs/MEMORY_ONE_PAGER.md`, `docs/FEATURES.md` s4, `docs/CHATBOT_PERSONA.md`, `docs/SCOPE_SETTLED_2026-10-26.md`. ## (a) Summary and the one principle
**Principle: earn the right to interrupt.** Every nudge must be something the user asked for, confirmed, or would thank us for, carry a one-line reason, and be stoppable in one word. Silence is the default; a nudge is a withdrawal from trust.
1. Friday already has an engine: triggers, dedupe, quiet hours (22-08), cap 3/day with digest overflow, ignore back-off (2 ignores = every other day, 3 = off 30 days), per-category stop, one-clause "why", per-topic mute, protected events, stale-means-dropped.
2. Gap 1: memory is a list of facts and events. It has no recurring-obligation model, no "open loop" model, no per-user timing and tone learning, no dismissal memory beyond ignore streaks.
3. Gap 2: triggers are mostly date-driven. Absence, after-event, open-loop and settled-scope (LPG, medicine, Paisa, parents) triggers are missing.
4. Gap 3: no score. Today candidates are sorted by urgency then due time; there is no value score or "which one of five do we send today".
5. Gap 4: the channel is text only. Voice note and call exist only as "user asked for it"; the morning check-in call is not built.
6. Gap 5: learning is only ignore-streak. We do not learn best hour, best channel, tone, or which topics a user values.
7. Gap 6: consent covers the user only; parents, group members (Paisa) and "people we message on the user's behalf" need their own state machine.
8. Gap 7: no measurement: nudge outcomes are stored but there is no useful-nudge rate, no daily review view, no kill switch per nudge type.
9. Phase 1 should ship 6 nudges on the smallest memory (section g), run in pilot "review mode" with the founder reading every nudge daily.
10. Compliance risk to check first: Meta's WhatsApp terms on general-purpose AI assistants and utility-vs-marketing template classification (section e).

## (d) The decision engine
Pipeline (reuse `ProactiveEngine.process`; add the new steps marked NEW):
1. **Candidates:** triggers.py, vendor_triggers.py and registered sources. NEW: open-loop, absence, LPG, medicine, parent and Paisa sources, each a pure function over memory.
2. **Score (NEW):** `value x urgency x freshness x user_affinity`. Value = Rs or time at stake plus "user asked for it" bonus; urgency = hours to deadline; freshness = decays after expiry; affinity = this user's past act-rate for the topic. Rule-based, no LLM. Deadline items (bills, medicine) can outrank everything; everything else competes for the day's slot.
3. **Gates (in order, existing first):** consent (user and recipient) -> user stopped topic -> ignore back-off -> quiet hours -> daily cap (3, rest to digest) -> NEW: topic cooldown (same topic not twice in 3 days unless deadline) -> NEW: "Is it already done?" check (bill paid, vendor booked) -> NEW: money-pattern gate: refuse any candidate built from an item with `confirmed=false`.
4. **Channel and timing (NEW):** default WA at the user's learned active hour, inside quiet-hour limits. Escalate WA -> VN -> CALL only if (a) the user marked the topic important, (b) the deadline is within the window, (c) no reply to the WA, (d) one escalation per item. Out-of-window WA must be an approved template.
5. **Wording from memory:** code assembles facts (names, dates, amounts); the model only rewords one sentence to the user's tone dials; fixed text for money and consent lines (engine already supports `fixed_text`). Every message: one-line reason + buttons [Haan] [Abhi nahi] [Rok do].
6. **Send, then learn:** record sent time, channel, tone; the reply, tap, ignore (24 h), snooze, stop and "galat" become signals.

**Hard rules:** daily cap 3 plus digest (exists); also weekly budget (open: founder set 2/week for marketing-like and 3/day for user-owned; pick one, see Q1); never urgency theatre ("last chance", countdown, fake scarcity); no nudge without a reason and an easy stop; back off after ignores (exists; add per-topic, not just per-kind); never nudge on unconfirmed money patterns; family and group-member consent gates apply per recipient; a user's own "remind me" never counts against the cap; calls only for important topics, 09:00-20:00 or the user's window.

**Learning timing and tone per user (small, explainable):** (1) best hour = hour bucket with highest reply rate over 30 days, needs 5 samples, else the default; (2) best channel per topic from act-rate; (3) tone dials from their own messages (existing persona) plus "too much / thik hai" feedback; (4) topic affinity = acted / sent, with a floor so one bad week does not kill a topic forever; (5) nothing is learned from content of other people's messages. All learned values are visible and editable ("tum mujhe kab message karti ho?").

## (e) Consent and safety
**Opt-in ladder:** L0 reply-only (nothing unprompted) -> L1 reminders the user asked for ("remind me") -> L2 follow-ups on things done together (bookings, quotes) -> L3 suggestions from remembered patterns (LPG, haircut cadence) -> L4 daily check-in / digest -> L5 calls. Move up only on an explicit yes in context ("Kya main bill 2 din pehle yaad dila diya karun?"), never bundled. Every rung can be dropped by one word. Default for new pilot testers = L1-L2.
**Per-topic controls:** bills, LPG, medicine, family, birthdays, vendors, savings, check-in, Wrapped; each with channel, quiet hours, on/off. Exists as `mute_topics` and autonomy categories; add medicine, LPG, paisa, parent as topics.
**Parent/child:** the parent is the data owner. Invite on the parent's own number with a plain-language consent (what the child will see, what not); consent stored with scope and date; withdrawal by one word stops summaries at once; the child never sees medicine names or call content unless the parent's scope says so. Elder mode: no payment or OTP by voice. Needs legal read.
**Group members (Paisa):** contacted only after the organiser confirms; first message says who asked, why, and "STOP"; maximum 2 reminders; no re-contact after STOP; no profile built on non-users (store amount and paid/not paid for the collection only, delete on close + 30 days).
**WhatsApp rules (sources: Meta developer pricing doc not fetchable here; third-party summaries, 2026-10-27):** business-initiated messages outside the 24 h customer-service window must be pre-approved templates; free-form replies only inside the window (multiple sources, e.g. https://www.courier.com/guides/whatsapp-pricing). Utility templates must be triggered by a user action or request; promotional text in a utility template can get it reclassified as marketing or rejected (https://m.aisensy.com/blog/how-to-write-whatsapp-utility-messages/, unverified, vendor blog). Billing: per delivered message; sources conflict on whether in-window utility messages are charged from 1 Oct 2026; India utility rate quoted as Rs 0.145 and marketing Rs 1.09 by one vendor, other sources differ (https://m.aisensy.com/blog/whatsapp-pricing-update-october-2026/, unverified). Plan: submit 5-6 generic utility templates early (reminder, due-date, follow-up, summary, check-in, Paisa-member); keep each strictly transactional so it stays utility (cheaper, fewer blocks); budget per user per month in the pilot.
**Meta AI-provider ban risk:** Meta's WhatsApp Business terms bar general-purpose AI assistants from the Business API (enforced from 2026-01-15), allowing business customer-service bots; India exemption unclear (https://techcrunch.com/2025/10/18/whatssapp-changes-its-terms-to-bar-general-purpose-chatbots-from-its-platform, plus MediaNama 2025-10). Friday is task-specific (errands, calls), but it also chats and answers simple questions: the lawyer and a BSP must confirm Friday is not treated as "general-purpose". This is a launch-blocking check.
**TRAI:** TCCCPR 2018 and the Second Amendment (12 Feb 2025) cover SMS and voice calls: mixed transactional-plus-promotional content is treated as promotional; implied consent for service messages lasts only for the contract; service/transactional voice calls use 1600-series, promotional 140-series (https://khaitanco.com/thought-leadership/Efforts-to-Curb-Spam-Continue-TRAI-Releases-Second-Amendment-to-the-TCCCPR-2018). I found no source saying WhatsApp is covered or excluded (unverified, needs lawyer). Our rule: no promotional content anywhere, so every call/SMS stays service/transactional; use the correct number series and DLT-registered SMS templates for fallback SMS.
**DPDP:** Rules notified 13-14 Nov 2025 with phased commencement; consent-manager phase from about Nov 2026; main obligations later (about 18 months; exact dates unverified, https://www.jsalaw.com/wp-content/uploads/2025/11/JSA-Prism-InfoTech-November-2025-DPDP-Rules.Final_.pdf). Law requires withdrawal as easy as giving consent (s6(6), per KPMG note), so "Rok do" must work in one word on any channel. Design for compliance now: purpose-limited memory, itemised consent per purpose (nudges, family, savings), notice in plain Hinglish, deletion, minimal prompts, retention (episodes 365 d, transcripts 30 d), children's data (a minor's data needs a guardian's consent: do not onboard under-18s).
**Founder lawyer must check:** (1) Meta "general-purpose" clause and AI-disclosure for Friday; (2) utility vs marketing classification of each template; (3) whether TCCCPR touches WhatsApp or only SMS/voice, and our call number series; (4) DPDP: consent artefact for parent summaries and for non-user group members; processing of health (medicine) data; (5) Paisa collector reminders to non-users and payment-regulation limits; (6) DND and "call back" rules for proactive outbound calls to the user; (7) retention and a data-fiduciary notice; (8) liability if a medicine or bill nudge is wrong.

## (f) Measurement
**North star:** useful-nudge rate = nudges the user acted on or rated "useful" / nudges sent (target set after week 1; start by watching, do not invent a target). Secondary: time saved (minutes per task, estimated and shown with method).
**Guardrails:** mute/stop rate per topic (alarm: >10% of recipients of a topic stop it in a week, a placeholder to tune); complaint rate (any "spam", "band karo", report on WhatsApp = counted; zero tolerance for non-user complaints); ignore rate (24 h no reaction); quiet-hour violations (must be 0); wrong-fact nudges ("galat": must be 0 for money and medicine); WhatsApp quality rating and template pauses; cost per nudge.
**Per-nudge:** reply/act rate, time to act, downstream task completed, "useful?" thumb (optional one-tap after 1 in 5 nudges).
**Pilot method (5-10 testers):** every nudge is logged with trigger, memory used, score, gates passed, wording, channel, outcome. Daily 10-minute founder review of all nudges sent and all suppressed-by-gate, marking each good / mistimed / wrong / creepy; weekly 1-line call with each tester. Pilot starts in **review mode** for new nudge types: the nudge is shown to the founder (or sent to the tester only after approval) for the first 3 days.
**Kill switch:** `proactive_enabled` global off exists; add per-topic and per-user switches in config, a "pause all Friday nudges for 24h" user command, and an auto-pause when a topic hits the stop alarm or any non-user complaint arrives.
